# 证据与口径（去 AI 味的核心）

「AI 味」最大的来源不是配音，而是**内容只有对产品有利的、无出处的断言**。规则：

## 1. 证据先于文案

每条要上画面的说法先落成记录，再写文案：

```
claim（一句话结论）/ value（数字）/ source（URL）/ source_type / caveat（口径）
```

- `source_type`：official（官方页面）/ third-party（独立机构）/ media（媒体报道）/ vendor（厂商自报）
- **厂商自报的 benchmark 不写成"绝对第一"**，页面要给出对比对象、口径和标签
- 抓不到官方页面时用「来源卡」：官方页面标题 + 日期 + URL + 口径标签，不要虚构截图

## 2. 数字必须交叉验证

发布类新闻至少交叉两处：官方原文 + 一家独立媒体或第三方评测。重点核对：

- 定价与订阅档位（官方开发者页为准）
- benchmark 分数与**测试口径**（第三方独立运行 / 厂商自报 / 混合）
- 上下文窗口的精确值（常写作 1,048,576 这类数字）

典型陷阱（实例）：厂商对比表里 SWE-Marathon 领先，但模型卡自己注明**部分竞品跑在自家编码工具里，非受控对比**；而独立第三方指数（Artificial Analysis）上该模型反而落后于对手。只报前者就是 AI 味。

## 3. 平衡视角必须有

- 至少一页给**第三方独立评测**，并在页脚标注「独立评测，非官方自测」
- 至少一页给**落后项**（"也有落后的地方"），用同样的版式呈现
- 局限要具体（默认开启的数据贡献模式、无 API、无权重），不要泛泛的"仍需改进"

## 4. 口播去 AI 味

- 短句、第一人称、每句接上一句
- 禁止"这标志着""让我们拭目以待"类空话
- 数字只在"增长/累计"本身是内容时滚动
- 每个观点只留一个主信息点

## 5. 真实素材接入（网络恢复后）

证据页组件支持真实截图：把官方页面截图放入 `public/evidence/`，命名与页面 prop 对应即可优先使用真实截图 + 荧光高亮；未取到时回退为来源卡。

截图方法（本机 Chrome）：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --disable-gpu --hide-scrollbars --virtual-time-budget=12000 \
  --window-size=1440,1000 --screenshot=public/evidence/xxx.png "<官方URL>"
```

## 6. 交付物

每条片子的交付目录（`审阅/NN_片名/`）：

- 成片 MP4
- `封面.jpg`（首帧）
- `联系表.jpg`（全片缩略墙，快速人工检查）
- `素材来源与口径.md`（上表）

交付前跑一遍技术校验：ffprobe 读流、时长、响度（目标约 -14 LUFS，实测 mean ≈ -28 dB 属正常叠加电平）、抽帧无黑帧、字幕不越界。

---

## 7. 素材选择：跟着论点走（重要）

"加素材"不是"有什么用什么"，先判断这个论点需要什么证据：

| 论点类型 | 该用 | 不该用 |
|---|---|---|
| 发布本身 | 官方标题视觉、新闻稿截图 | 自绘海报 |
| 能力 / 功能 | 产品界面截图、官方演示视频 | 人物采访画面 |
| 数据 / 跑分 | 官方 benchmark 表格、第三方榜单截图 | 无来源的自绘柱状图 |
| 定价 / 可用范围 | 官方定价页截图 | 只靠口播说数字 |
| 安全 / 政策 | 官方政策原文截图 | 空泛结论 |
| 训练 / 基础设施 | 数据中心照片、官方架构图 | 通用科技背景 |

判断口诀：**人物脸只回答"谁在说"，产品界面才回答"它能做什么"。** 采访视频/高管照片只在讲团队或引用原话时用，不要拿来当产品能力的证据。

## 8. 素材采集流程（可执行）

1. 抓官方新闻稿 HTML，正则提取 `wp-content/uploads/...{png,jpg,mp4,webp}` 与 `srcset`——官方页面的 social share 图、正文配图、演示视频都能这样拿到。
2. Chrome headless 整页截图（1440 宽，高度按需）：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --hide-scrollbars --virtual-time-budget=15000 --window-size=1440,1800 \
  --screenshot=public/official/page.png "<官方URL>"
```

3. 用 PIL 裁出证据区域，确认关键词清晰；**裁切边缘不要露出上下半截字**（上方残留段落结尾、下方下一行顶部）。
3b. 高亮坐标用 `measure_highlight.py <图>` 实测，不要目测：

```bash
python3 measure_highlight.py public/official/seg_takeaways.jpg
# 行04  y  51.0% -  57.5%  (h 6.5%)   x   6.1% -  62.1%
```

教训：按预览图比例估算，荧光笔会整体偏一行（盖到上一行或飘到右侧空白）。
4. 高亮坐标用百分比，套 `OfficialEvidence` 组件：整段原文 → 荧光笔只覆盖关键词 → 中文结论放空白处 → 页脚标来源与日期。
5. 视频素材先用 `ffmpeg -f null -` 验证可完整解码（下载被截断会报 `Invalid NAL unit size` / `partial file`），不可用的宁可不放。

## 9. 素材不足时怎么降级

- 官方页面不可达 → 用「来源卡 + 口径标注」，不要虚构截图
- 只有 interview 视频但论点讲产品 → 不用，改用官方原文截图
- 自绘图表必须带页脚：「来源：官方模型卡 / 第三方机构，口径说明」
- 交付文档里写清哪些拿不到、为什么、怎么补
