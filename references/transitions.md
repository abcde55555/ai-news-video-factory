# 转场与视觉母题

「生硬」的根源不是动效不够多，而是三件事：**镜头硬切、没有贯穿母题、版式是 PPT 不是产品**。
这类解说视频的精髓是「产品在现场」：

## ⚠️ 借鉴风格，不复制身份

借鉴是为了学**结构、节奏、版式、动效**，不是搬别人的身份标识。红线：

- ❌ 不要复用对方的名字、头像、Logo、账号名、水印
- ❌ 不要照抄文案（结构可以对齐，措辞必须自己写）
- ✅ 品牌水印用 `theme.ts` 的 `brand` 填**自己的**名字；默认为空即不渲染


## 0. 为什么「全片 dissolve」会显得黏、不动（逐帧实测结论）

对参考片与本项目成片做逐帧差异分析（10fps 采样、相邻帧 MAE），数据如下：

| 指标 | 参考片 | 我们的 v9 | 说明 |
|---|---|---|---|
| 硬切（单帧尖峰） | 11 次 / 215s | **0 次** / 281s | 我们没有任何干脆的切换 |
| 渐变事件 | 107 次（每 2 秒一次） | 76 次（每 3.7 秒） | 参考片的"渐变"多为页内小变化 |
| 帧差均值 | 1.55 | 0.79 | 页内运动量只有一半 |
| 静止帧占比 | 79% | 86% | 我们更"死" |

结论：**参考片是「硬切换页 + 页内内容持续生长」，我们是「所有切换都淡入淡出 + 页内一次性摆好」。**
交叉溶解用满全片，会让每次切换都“软”，没有节奏重音；观众感知为黏、平、不灵动。

参考片的转场语言实际有四类（逐帧抽帧确认）：

1. **硬切**：干脆换页，浅色页直接切深色页（diff 20-98）
2. **方块碎裂（block/mosaic dissolve）**：约 0.2-0.3s，画面被白色方块侵蚀再消散——用于场景/章节切换，赛博感强，契合 AI 题材
3. **同页内容生长**：构图不动，手机屏内容、右侧文字块依次“长”出来（不是一次性摆好）
4. **尺度跳变（zoom punch）**：同一页在台词重点处瞬间推近重构图，代替淡入

### 改造清单

- 章节切换：用方块碎裂，或直接硬切；不要用全屏 crossfade
- 普通换页：硬切（`TransitionSeries` 里不加 Transition 即为硬切）
- 页内：把元素入场按 cue 节奏**分批**排（每 2-3 秒一批），不要开场一次全进
- 保留 KenBurns，但它只是背景呼吸；主要动感来自元素生长与跳变
- 目标：硬切 8-12 次/3 分钟，渐变事件（含页内）≥ 60 次/3 分钟

### 改造成效实测（同一套指标复验）

| 版本 | 硬切 | 渐变 | 帧差均值 | 静止 |
|---|---|---|---|---|
| 改前（全 crossfade） | 0 | 76 | 0.79 | 86% |
| 改后（硬切 + 分批入场 + KenBurns 加大） | 7 | 95 | 0.85 | 86% |
| 参考片 | 11 | 107 | 1.55 | 79% |

**关键结论：硬切和分批入场能改善「节奏感」，但帧差（页内运动量）几乎不变。**
KenBurns 从 1.055 加到 1.09 只带来 0.06 的提升——整页缩放对帧差贡献极小。

帧差的真正来源是**内容本身的持续变化**：参考片帧差高，是因为手机屏里是真实录屏（聊天在滚动、按钮状态在变）。
纯矢量卡片页面的物理上限就在 0.8-0.9 附近。要突破，必须引入真实动态素材（官方演示视频/录屏）作为页内内容，而不是继续调动画参数。

判断口径：先看硬切数与渐变数是否达标（节奏层），再决定是否需要真实素材（信息层）。

## 1. 转场：画面被推走，不是切走

用 `@remotion/transitions` 的 `TransitionSeries`，**版本必须与 remotion 核心完全一致**
（如都是 4.0.410；装 latest 会 import 新版 remotion 才有的 export，运行时报 `Interactive not found`）。

```bash
npm install @remotion/transitions@<与remotion同版本>
```

结构（模板 `src/MuseWonder.tsx` 已实现）：

```tsx
<TransitionSeries>
  {SHOTS.flatMap((shot, i) => [
    i > 0 && <TransitionSeries.Transition presentation={...} timing={linearTiming({durationInFrames: 15})} />,
    <TransitionSeries.Sequence durationInFrames={s(shot.dur) + s(0.5)}>{shot.node}</TransitionSeries.Sequence>,
  ])}
</TransitionSeries>
```

**关键技巧：每个 Sequence 时长多给 0.5s（转场时长），镜头起点保持不变**——cue 时间码和配音完全不用重排，转场发生在每个镜头的"尾部补偿帧"里。

转场设计语言（有语义，不是随机）：
- 常规镜头：`slide({direction: 'from-right'})`——内容从右推入，主要方向
- **进入重点章节**：`from-bottom`——方向突变 = "这里最重要"
- 结尾：`fade()`——回归平静

## 2. 贯穿母题：手机 + 聊天界面

一个 `PhoneMockup` 组件贯穿全片：标题卡右侧 mini 手机（气泡弹出演示卖点）、故事段整屏聊天模拟。
**故事不用卡片讲，用对话讲**：用户气泡（上传材料）→ AI 打字指示器 → AI 主动推进（任务清单卡）→ 引用历史条款（引用卡）→ 关键动作弹确认卡。
消息弹出时间（镜头内相对秒）与 cue 时间码对齐，右侧大字标注（DAY 1/2/3）随解说切换。

布局大坑：**Remotion 的 `AbsoluteFill` 默认 `flexDirection: 'column'`**——想要左右并排必须显式写 `flexDirection: 'row'`，否则子元素垂直堆叠被挤出画面（症状：元素"消失"或在画面底部露出一条）。

## 3. 版式要有「产品感」

信息卡（四宫格/对比条）适合规格与数据段；但叙事段必须回到产品 UI 模拟。判断标准：**观众觉得在"看一个 app 工作"，而不是"看幻灯片"**。UI 模拟的真实感来自细节：状态栏（9:41+电池）、对话头（头像+在线状态）、输入栏、附件条、打字指示器、按钮的点击态。

## 4. 冒烟渲染先看转场帧

转场帧（镜头起点后 0~0.5s）最容易出问题：`--frame` 取转场中间帧，确认两个画面混合时没有穿帮。
